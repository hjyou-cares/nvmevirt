3. 핵심 검증 결과
-----------------

- SLC-only: host read/write가 SLC에서만 발생, migration/TLC GC 0.
- Overflow: SLC internal read 566,781 pages와 TLC internal write 566,781 pages 일치.
- CRC32C: 네 migration 정책 모두 data mismatch 없이 통과.
- Extended suite: 60/60 완료, fio error 및 조건 누락 0.
- Crossover: 6/6 완료.
  - Resident: SLC throughput +23.5%, p99.9 -44.3%.
  - Overflow: throughput +16.9%이나 p99.9 +76.2%.
  - Sustained: throughput 차이 +0.6%, p99.9 13.6배, erase 3.43배.
- Policy:
  - Zipf에서는 Cost-Benefit이 migration page 최소, FIFO가 peak erase 최소.
  - Hot-cold에서는 FIFO가 throughput/p99/SLC copy/TLC GC copy/peak erase 종합 우위.
  - Uniform에서는 정책 간 차이가 작아 locality 의존성을 확인.


4. 재현 명령
------------

보고서 Word 재생성:

  python3 report/build_practice2_docx.py

확장 결과/그림 재생성:

  python3 report/make_practice2_extended_figures.py
  python3 report/make_slc_crossover_figure.py --reps 1

서버 실험의 공통 원칙:

  umount -> rmmod -> insmod -> mkfs -> mount -> counter reset -> fio

정책 또는 ratio를 바꿀 때 모듈을 완전히 다시 적재해야 이전 FTL의 line/mapping/
write-pointer 상태가 다음 run에 섞이지 않는다.
